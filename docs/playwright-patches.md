# Playwright driver patches

Cloakium ships a patched `playwright-core` so that the driver stops asking
Chromium for automation surfaces it does not need, without changing the public
Playwright API. Everything outside the patch set is stock upstream code.

- Upstream package: `playwright-core@1.65.0` (Apache-2.0)
- Patch set: this repository's own MIT code, applied by `tools/playwright-patcher`
- Source of truth for the download: `upstream.json` (`playwright.*` for the npm
  tarball, `chromium.version` for the Chromium build the driver is paired with)
- Target file: `lib/coreBundle.js` (the npm package ships a pre-bundled driver)
  plus one `package.json` metadata block

No third-party patch project's code, text or naming is used here. The two
published Playwright forks that solve similar problems were read as public
documentation of the *problem space* only; the implementation below is original
and was validated against a real Chromium 157 build.

## Why the driver, not the browser

`navigator.webdriver`, UA strings and canvas noise are browser-level concerns and
belong to the Chromium patches (`docs/native-patches.md`). The driver has its own
observable surface which cannot be fixed from the browser side:

- `Runtime.enable` / `Console.enable` turn on V8's console instrumentation and
  the `Runtime.*` event stream. On several Chromium generations that installs an
  accessor for `window.console`; on Chromium 157 it does not (measured, see
  "Measurements"), but the domain still exposes context and exception events the
  page should not have to pay for.
- Playwright needs execution contexts for `page.evaluate`, selectors, workers,
  service workers and tracing. Upstream obtains them from
  `Runtime.executionContextCreated`, which only exists while the Runtime domain
  is enabled.

So the patch set replaces that dependency with explicit CDP discovery and then
never enables the domain.

## Patch inventory

| Patch | File | What it does |
| --- | --- | --- |
| `0001-cloakium-shared-helpers` | `lib/coreBundle.js` | Adds file-scope helpers: the `CLOAKIUM_RUNTIME_DOMAIN` gate and a random utility-world name (`w_` + 16 hex chars) replacing the static `__playwright_utility_world_<guid>` prefix. Allocates the per-page discovery map. |
| `0002-cloakium-frame-contexts` | `lib/coreBundle.js` | Drops the unconditional `Runtime.enable`, discovers main/utility contexts per frame, re-discovers on commit, re-registers bindings per context, and replaces the Android-webview `Runtime.disable/enable` retry loop with discovery. |
| `0003-cloakium-context-readiness` | `lib/coreBundle.js` | `Frame.context()` awaits the delegate's in-flight discovery before reading the context promise, so a lazy/eager race can never return a stale or unresolved context. |
| `0004-cloakium-worker-contexts` | `lib/coreBundle.js` | Dedicated workers: derives the worker context from `Runtime.evaluate("globalThis")` instead of `Runtime.enable`. |
| `0005-cloakium-service-worker-contexts` | `lib/coreBundle.js` | Service workers: same derivation, plus the `<143` `workerScriptLoaded()` handshake that upstream fed from the context event. |
| `0006-cloakium-launch-arg-hygiene` | `lib/coreBundle.js` | Filters `--enable-automation` out of the Chromium command line even if a future upstream or a caller adds it. |
| `0007-cloakium-set-content-liveness` | `lib/coreBundle.js` | `frame.setContent()` normally waits for a `console.debug` marker, which needs the Runtime domain; without it the new document's load lifecycle is the completion signal. |

The `cloakium` block in `package.json` is **not** a patch. It is generated by the
patcher at apply/check time from the package that is actually being patched: the
name, version and licence come from the pristine `package.json`, the tarball URL
is derived from `name@version`, and `patchSet` comes from `--patch-set`. No
upstream version string appears anywhere in `patches/playwright/`, so bumping
Playwright only re-validates code hunks — there is no metadata hunk to break.

Each patch is a plain unified diff, replayed with zero fuzz.

## How contexts are discovered

Discovery is **on demand**, keyed by the frame's current document object: the
first `Frame.context()` call after a document swap performs it, and the result
is cached per document. Navigation handling only *invalidates* the previous
contexts (so a destroyed context can never be handed out); it does not issue CDP
traffic from inside the `Page.frameNavigated` handler, which keeps the protocol
stream free of re-entrant requests during commit. If Chromium is still settling
the new document, the discovery loop retries for up to ~0.5s before giving up.

One ordering rule matters for the initial document: `Page.lifecycleEvent`
listeners must be registered synchronously in the `Page.getFrameTree` handler.
`launchPersistentContext()` waits for the default page's `load` lifecycle, and
the initial document emits it immediately after the frame tree arrives; awaiting
context discovery before attaching the listener loses that event and hangs
persistent startup. Discovery is therefore returned from the handler and awaited
by `_initialize`, not awaited in the middle of it.

For each frame it asks Chromium for two context ids:

- **Utility (isolated) world** — `Page.createIsolatedWorld` with the page's
  random world name; the reply carries `executionContextId`.
- **Main world** — the object id returned by
  `Runtime.evaluate({ expression: "globalThis", serializationOptions: { serialization: "idOnly" } })`
  ends in the execution context id. For a frame that is not the session's own
  target (same-process child frame), the driver instead follows
  `DOM.getFrameOwner` → `DOM.describeNode` → `DOM.resolveNode` on the frame's
  `contentDocument` and derives the same id.

Both ids are fed into the existing `_onExecutionContextCreated` path, so
`FrameExecutionContext`, selector resolution, `page.evaluate`, console-message
mapping and tracing see ordinary contexts.

Out-of-process iframes are separate CDP sessions and each runs the same
discovery for its own target, so `frame.evaluate()` works across processes.

Bindings need one extra step: `Runtime.addBinding` only applies to contexts that
already exist when the domain is off, so every discovered main-world context
gets `Runtime.addBinding({ name, executionContextId })`. `exposeFunction`
therefore keeps working across navigations; the smoke suite covers both the
before- and after-navigation cases.

## Runtime domain opt-in

`CLOAKIUM_RUNTIME_DOMAIN=1` restores the upstream behaviour: the driver sends
`Runtime.enable` and skips its own discovery, which brings back `page.on("console")`
and `page.on("pageerror")` at the cost of the domain being observable again.

Without it, console and page-error events are **not** delivered. This is a
deliberate, documented trade-off rather than an accident:

- console output is available from the wrapper's own logging or from
  `page.evaluate` return values;
- nothing in the selector, worker, tracing, routing or binding surface depends
  on it.

The switch is read per page at setup time, so a process can serve both modes.

## Measurements on Chromium 157.0.8103.38

Recorded with the patched driver against a local Chromium 157 build:

- `window.console` stays a plain data property with and without
  `Runtime.enable`, so the historical accessor leak is already gone on this
  Chromium. The patch still removes the domain because it is a needless
  event surface and because older Chromium generations do instrument the
  console.
- `navigator.webdriver` is `true` under Playwright regardless of this patch set.
  It is a consequence of the `--remote-debugging-pipe` transport, not of
  `--enable-automation` (that switch is not passed by upstream 1.65 and the
  patch set strips it defensively anyway). Cloakium therefore does **not**
  spoof `navigator.webdriver` from page script; the property keeps its native
  getter. Browser-level identity work belongs to the Chromium patch set.
- `HeadlessChrome/157.0.0.0` remains in the default user-agent string. The
  driver does not rewrite it; a wrapper may pass `userAgent` explicitly, which
  is ordinary public API.

## Build and verification

```sh
# Reproduce the patched tree outside Nix
tools/playwright-patcher/target/debug/playwright-patcher \
  apply --source <unpacked playwright-core> --target <out> \
  --patches patches/playwright --patch-set playwright-1.65.0

# Verify only (no writes)
… check --source <unpacked playwright-core> --patches patches/playwright

# Nix package (exposes .libPath, .version and bin/playwright)
nix eval .#playwright.libPath
```

`nix/playwright.nix` builds `tools/playwright-patcher` with
`rustPlatform.buildRustPackage` from the committed `Cargo.lock`, fetches the npm
tarball pinned by `upstream.json`, replays the patch set, and keeps upstream's
`LICENSE`, `NOTICE` and `ThirdPartyNotices.txt` in place. It adds a short
`CLOAKIUM-NOTICE` (Apache-2.0 §4(b) change statement) and
`CLOAKIUM-PATCHES.json` (patch names, SHA-256 of each patch, before/after
digests of each modified file — no timestamps, so the file is diff-stable).

Install checks inside the derivation verify that the `cloakium` marker exists and
matches the package version, that the unconditional `Runtime.enable` line is
gone, and that `bin/playwright --version` runs.

Driver-level behaviour is covered by `tests/driver/smoke.mjs`, which only talks
to a local HTTP server:

```sh
CLOAKIUM_BINARY_PATH=/path/to/chromium node tests/driver/smoke.mjs
```

It resolves `playwright-core` from the project root (the wrapper's symlink to
the patched `libPath`); set `CLOAKIUM_PLAYWRIGHT_CORE` to a package directory for
ad-hoc runs, and `CLOAKIUM_DRIVER_TIMEOUT_MS` to bound the whole run. The suite
covers navigation, locators, shadow DOM, same-process and
cross-site iframes, reloads, worker and service-worker evaluation, bindings
before and after navigation, routing, `setContent`, popups, tracing, the console
and page-error opt-in, and the invariant that `navigator.webdriver` keeps its
native getter. `tests/driver/persistent.mjs` (run from the same entry point) adds
the persistent-context surface: default-page readiness, close/relaunch on one
profile directory, pre-existing profile artifacts, context options,
`browser().newContext()` rotation while the default page stays alive, and
navigation inside a persistent context. Every persistent operation is bounded to
5s so a startup regression fails fast instead of stalling the suite.

The applier itself is unit- and integration-tested (`cargo test`), including:
mutated hunk rejection, already-applied/reversed detection, ambiguous match
rejection anywhere in the file, a 25k-line legitimate offset, the opt-in
`--max-offset` diagnostic, marker derivation from a simulated next release, and
CLI behaviour (empty-target requirement, `--check` writes nothing).

## Patch matching

Hunks are exact: every context and removed line must match byte for byte. By
default the **whole file** is searched and the match must be unique, so upstream
edits that merely move code cannot break a patch. Ambiguous matches, reversed
matches and overlapping hunks are hard errors. `--max-offset <N>` narrows the
search to a window around the declared line for diagnosis only; it is not part
of the normal build.

## Validating a candidate release before the pin moves

`nix/playwright.nix` takes an optional `upstreamInfo` argument that defaults to
`upstream.json`, so a candidate can be built and tested without touching the
default pin:

```nix
pkgs.callPackage ./nix/playwright.nix {
  nodejs = pkgs.nodejs_26;
  upstreamInfo = {
    playwright = {
      version = "1.65.1";
      url = "https://registry.npmjs.org/playwright-core/-/playwright-core-1.65.1.tgz";
      hash = "sha256-…";          # nix store prefetch-file
      chromiumVersion = "159.0.8154.6";
      browserRevision = "1255";
    };
    chromium.version = "157.0.8103.50";
  };
}
```

The driver suite accepts `CLOAKIUM_EXPECTED_PLAYWRIGHT_VERSION` for the same
purpose: without it the suite checks the repository pin from `upstream.json`;
with it, the fixture asserts the candidate version instead. Production runs keep
checking the root pin.

## Updating to a new Playwright release

1. `npm view playwright-core@<version> dist.integrity dist.tarball` and prefetch
   the tarball; record `version`, `url`, `hash` (SRI SHA-256) and the Chromium
   `browserVersion` / `revision` from `browsers.json` under `playwright` in
   `upstream.json`. `chromium.version` is a separate field: it tracks the actual
   native Nix Chromium pin, which is deliberately one Chromium major behind the
   Chrome-for-Testing build Playwright downloads (1.65 ships CfT 158 while the
   driver is validated against 157).
2. Run `playwright-patcher check`. Only genuine code drift fails, and it fails
   with the exact line that changed — regenerate that one hunk.
3. Re-run `cargo test` and `tests/driver/smoke.mjs`.

No metadata patch has to be edited: the `cloakium` marker, its version, its
patch-set label and the tarball URL are derived from the package being patched
and from `--patch-set`, which `nix/playwright.nix` passes as
`playwright-<version>` from `upstream.json`. A release that only changes
`package.json` and leaves the driver bundle compatible patches cleanly and
produces a marker for the new version.

## Residual known artefacts (not patched)

- `window.__playwright__binding__controller__` appears once
  `exposeFunction`/`exposeBinding` is used. The name is baked into the bundled
  injected script, which is shipped as a string constant; renaming it would mean
  rewriting that embedded source, so it is left alone and documented instead.
- `Runtime.addBinding` is still visible to a page that enumerates CDP bindings;
  removing it would remove `exposeFunction`.
- DevTools integration (`crDevTools`) and the Electron/CDP-connect paths keep
  their `Runtime.enable`; they are only reached for `devtools://` targets,
  `connectOverCDP` and Electron, none of which is a launched Cloakium browser.
- The Firefox, WebKit and WebDriver-BiDi drivers keep upstream's static
  `__playwright_utility_world__` name and their `Runtime.enable`; Cloakium only
  launches Chromium, where the name is randomised and the domain is gone.
